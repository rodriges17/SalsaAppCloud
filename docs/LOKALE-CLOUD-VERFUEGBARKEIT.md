# Lokale Cloud-Verfügbarkeit

`cloud-local.js` entscheidet die lokale Cloud-Verfügbarkeit über `resolve(revision, figures, { figureId, revisionIds })`. Dieses Interface ist zugleich Testoberfläche. Bibliothekskarten, eigene Cloud-Figuren und die Übernahme verwenden dieselbe Entscheidung. `importCandidates` verwendet dieselben Herkunftsdaten für die ausdrückliche Wahl zwischen Ersetzen und neuer Kopie. Herkunft (`status`) bleibt von Lesbarkeit und Cloud-Berechtigungen getrennt.

Ein Ergebnis beschreibt eine vollständige aktuelle Kopie (`available`), eine Teilkopie (`partial`), eine ältere lesbare Version (`outdated`), fehlenden Ordnerzugriff (`access-required`), fehlende Dateien (`missing`) oder fehlende lokale Zuordnung (`cloud`). Eine einzelne vollständige lesbare Kopie hat Vorrang. Mehrere Teilkopien werden nicht zu einer vollständigen Kopie zusammengerechnet. `current` bezeichnet ausschließlich die vollständig verfügbare aktuelle Kopie; `figure` kann auch eine ältere oder teilweise verfügbare lesbare Kopie bezeichnen. `modified` beschreibt lokale Inhaltsänderungen, nicht Lernstandänderungen.

Eine lokale Inhaltsänderung an einer zuvor vollständig zugeordneten Kopie bleibt eine nutzbare lokale Anpassung. Die Zuordnung merkt sich weiterhin die ursprünglich übernommenen Cloud-Videos; außerhalb der App fehlende oder veränderte Dateien werden durch die Speicherprüfung gesondert gesperrt. Eine Teilübernahme wird durch nachträgliche Textänderungen nicht vollständig.

Ältere Versionen werden anhand der stabilen Cloud-Figur oder bekannter Versions-IDs erkannt; allein gleiche Titel sind kein Versionsnachweis. Die alte Kopie bleibt ausdrücklich zu öffnen. Beim Einzelimport ist Ersetzen eine ausdrückliche Wahl. Ein Sammeldownload ergänzt unveränderte Teilkopien, erstellt für lokal angepasste Teilkopien eine zusätzliche Kopie und überschreibt keine ältere oder angepasste Figur automatisch. Inhalte mehrerer Teilkopien dürfen bei diesem bewussten Download wiederverwendet werden, müssen aber anschließend als eine vollständige Figur gespeichert sein.

Die Speicher-Adapter liefern den aktuellen Bestand: App-Speicher prüft Metadaten und das Vorhandensein von Cache-Einträgen, Geräteordner prüfen Zugriff, Größe und Änderungszeit. Für die Statusdarstellung werden keine vollständigen Videos eingelesen oder gehasht. Vollständige Integritätsprüfung bleibt beim Lesen, Speichern und Übernehmen. Diese Existenzprüfung ist kein kryptographischer Integritätsnachweis.

Bei lokalen Änderungen, Nachrichten anderer App-Tabs, Rückkehr in die App und erneuter Cloud-Ansicht wird der Bestand erneut geprüft. Eine Generation verhindert, dass verspätete Prüfungen eine neuere Bestandsantwort ersetzen. Die Kontowechselbehandlung verwirft ebenfalls alte Prüfungen. Vor dem Öffnen einer lokalen Cloud-Kopie wird erneut geprüft.

Die Implementation bleibt für Android und PWA identisch. Bestehende Geräteordner-, Medien-Sitzungs- und Cloud-Lesestand-Module behalten ihre Verantwortung. Tests: `cloud-local.test.js`, `cloud-library-download.test.js` und der gemeinsame Oberflächenvertrag `cloud-local-state` sowie `cloud-repair-missing` / `cloud-repair-modified`.
